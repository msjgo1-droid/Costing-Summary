# Costing Bulk SUMMARY 자동 생성기

SUBMITTED 원가(costing) 엑셀 파일에서 시즌·스타일·DESCRIPTION과, 스타일/컬러웨이별
가장 최근 제출분의 내부(제안)/오픈(개정) FOB·CM·MARGIN%·REMARK를 자동으로 추출해서
`Costing Bulk {시즌} {브랜드} - SUMMARY` 형식의 엑셀 파일을 만들어주는 Streamlit
앱입니다. 기존 SUMMARY 파일을 함께 업로드하면 새 제출 데이터로 값을 덮어써서
업데이트할 수도 있습니다. 생성된 SUMMARY의 내부CM/오픈CM(노란 배경 칸)을 수정하면,
CM은 FOB 안에 포함된 원가 항목이므로 그 변동분만큼 해당 FOB도 같이 움직이고
내부MARGIN%도 자동으로 다시 계산되도록 수식으로 들어갑니다 (내부/오픈은 서로 독립적으로 움직입니다).

## 로컬에서 바로 실행하기

```bash
pip install -r requirements.txt
streamlit run app.py
```

실행 후 터미널에 나오는 주소(기본 http://localhost:8501)를 브라우저로 열면 됩니다.

## GitHub + Streamlit Community Cloud로 배포하기 (무료, 약 5분)

1. GitHub 계정이 없다면 https://github.com 에서 무료로 가입합니다.
2. 새 저장소(Repository)를 만들고, 이 폴더 안의 파일들(`app.py`, `parser.py`,
   `summary_builder.py`, `pipeline.py`, `requirements.txt`)을 모두 업로드합니다.
   - GitHub 웹사이트에서 "Add file → Upload files"로 드래그 앤 드롭하면 됩니다.
3. https://share.streamlit.io 에 접속해서 GitHub 계정으로 로그인합니다.
4. "New app"을 누르고 방금 만든 저장소를 선택합니다. Main file path는 `app.py`로 지정합니다.
5. "Deploy"를 누르면 몇 분 안에 `https://(이름).streamlit.app` 형태의 고유 웹사이트 주소가
   생깁니다. 이 주소를 팀원과 공유하면 누구나 브라우저에서 파일을 업로드해 SUMMARY를
   만들 수 있습니다.
6. 이후 코드를 수정하고 싶으면 GitHub 저장소의 파일만 업데이트하면 배포된 사이트에
   자동으로 반영됩니다.

## 사용 방법

1. 왼쪽에서 시즌, 브랜드명, (선택) 파일명에 붙일 설명을 입력합니다.
2. `...-SUBMITTED.xlsx` 형식의 원가 파일을 1개 이상 업로드합니다.
3. 기존에 쓰던 SUMMARY 파일이 있으면 함께 업로드합니다. (없으면 새로 생성됩니다)
4. "데이터 추출" 버튼을 눌러 자동 추출 결과를 확인합니다. (스타일/컬러웨이별로 한 줄씩,
   가장 최근 제출분의 FOB/CM/MARGIN%만 표시됩니다)
5. 표에서 잘못 추출된 값(스타일명, DESCRIPTION, STAGE 라벨, FOB/CM/MARGIN % 등)을 직접 수정합니다.
6. "SUMMARY 엑셀 생성" 버튼을 눌러 완성된 파일을 다운로드합니다.

## SUMMARY 파일 컬럼 구성

`Season | Style/Colour | Style Description | Stage | 내부FOB | 내부CM | 내부MARGIN% | 오픈FOB | 오픈CM | REMARK`

스타일/컬러웨이별로 **한 줄**만 있으며, 그 줄의 값은 가장 최근 제출분의
값입니다. 원가 시트의 좌측(제안/내부)과 우측(개정/오픈) 값을 각각 따로 담습니다.
오픈MARGIN%는 원본 파일에 별도 셀 자체가 없어(계산 로직을 알 수 없어) 컬럼을 두지 않습니다.
STAGE 칸은 그 값이 어느 단계(P1/P2/P3, GTM1/GTM2, SMS, PP)에서 나온 것인지
알려주는 참고용 표시입니다. Style Description이 비슷한 항목끼리(성별 접두어 M/W를
뗀 이름 기준) 자동으로 묶여서 정렬되며, 같은 그룹 안에서는 M(남성)이 W(여성)보다
위에 오도록 정렬됩니다. 파일명에 띄워쓰기가 안 되어 있어도(예: `SkysummitCapacityShort`)
대문자 경계를 기준으로 띄워쓰기를 넣어 같은 그룹으로 인식합니다.

## CM 수정 시 FOB·마진 자동 재계산

CM(Cut & Make)은 FOB 가격 안에 포함되어 있는 원가 구성요소입니다 (FOB = 원부자재비 등
기타 고정비용 + CM). 그래서 CM을 바꾸면 그 변동분만큼 FOB도 같이 움직입니다. FOB는
내부/오픈이 서로 독립적으로 움직입니다:

- **내부CM**을 바꾸면 → **내부FOB**만 바뀝니다.
- **오픈CM**을 바꾸면 → **오픈FOB**만 바뀝니다 (오픈MARGIN%는 컬럼 자체가 없습니다).

FOB 계산식은 다음과 같습니다.

```
FOB_new = FOB_기준값 + (CM_new - CM_기준값)
```

여기서 "기준값"은 SUMMARY를 생성한 시점의 FOB·CM 값입니다. 내부FOB의 기준값은 원가
시트의 CBS 확정가 칸(좌측)이 아니라 'Net' 행(내부/제안 쪽 항목만 전부 더한 값, CM
포함)에서 가져옵니다 — CBS 확정가 칸(좌측)은 파일 안에서 오픈쪽 값을 그대로 가져오는
수식으로 되어 있어(미러링), 그 값을 그대로 쓰면 내부FOB가 항상 오픈FOB와 똑같아져
버리기 때문입니다.

**내부MARGIN%**는 원본 파일의 실제 마진% 수식과 동일하게 다음 식으로 계산됩니다.

```
내부MARGIN%_new = 1 - (내부FOB_new / 오픈FOB_new)
```

이 식은 내부FOB뿐 아니라 오픈FOB에도 좌우되므로, **내부CM과 오픈CM 중 어느 쪽을
바꾸어도 내부MARGIN%는 함께 재계산됩니다** (오픈CM만 바꿔도 분모인 오픈FOB가 바뀌기
때문입니다).

이 기준값들은 `계산정보`라는 별도 시트에 저장해두고, SUMMARY의 FOB·MARGIN% 칸에는 그
기준값과 현재 CM 칸(또는 서로의 FOB 칸)을 참조하는 실제 엑셀 수식을 넣습니다.
`계산정보` 시트는 계산용이므로 직접 값을 고치지 않도록 주의해주세요. 이 계산에 필요한
정보를 원본 파일에서 찾지 못한 행은 수식 대신 고정된 값만 표시되고 검토 표시가 남습니다.

## 추출 규칙

- **시즌 / 스타일 / DESCRIPTION**: 파일명 앞부분 `F27-1234567_M FlyLux ...` 형식에서 추출
- **제출일자 / FOB**: 각 시트의 `CBS <날짜> $<가격>` 문구 기준 (시트 탭 이름이 아님)
- **가장 최근 값만 표시**: 여러 번 제출된 이력이 있어도 컬럼이 늘어나지 않도록, 스타일/
  컬러웨이별로 가장 최근(제출일이 가장 늦은, 동점이면 시트 탭이 더 왼쪽/최신인 쪽) 제출분의
  FOB/CM/MARGIN%만 한 줄로 남깁니다. 시트 탭 이름에서 단계(`P1`/`P2`/`P3`, `GTM1`/`GTM2`,
  `SMS`, `PP`)를 찾아 STAGE 칸에 참고로 표시합니다 (한 시트 이름에 단계가 여러 개
  들어있으면, 예: `GTM2-F27 PP 6.03`, 이름에서 더 앞쪽에 나온 단계를 사용). 단계 키워드를
  전혀 못 찾으면 시즌 표기(S27/F27 등)는 제외하고 시트 이름의 다른 부분을 임시로 사용합니다.
- **내부/오픈 FOB·CM**: 원가 시트의 좌측(제안/내부)과 우측(개정/오픈) 값을
  각각 따로 읽어옵니다. 오픈 쪽 값이 파일에 없으면 내부 값으로 보완합니다.
  오픈 MARGIN%는 원본 파일에 별도 셀 자체가 없어 SUMMARY에 컬럼을 두지 않습니다.
  SOLID/HEATHER가 한 시트에 같이 들어있는 경우(주로 파일명에 FlyLux가 들어간 스타일)는
  컬러웨이 블록마다 따로 읽어옵니다.
- **REMARK**: CM 옆 우측 REMARK 칸 중 노란색 강조 셀의 내용. 노란색이 아니면 `[검토 필요]` 표시
- **단계별 변경점**: 시트가 여러 개면, 노란색으로 강조된 값이 이전 단계 대비 바뀐 항목을
  자동으로 REMARK에 함께 기록 (참고용, 검토 필요)
- **스타일번호 불일치 차단**: 시트 안에 적힌 스타일번호가 파일명의 스타일번호와 다르면
  데이터 품질 문제로 보고 해당 블록은 자동으로 무시하고 경고 메시지로 안내합니다.
- **기존 SUMMARY 파일 업데이트**: 예전 방식(날짜/단계별로 컬럼이 여러 개 있던 파일)도
  인식해서, 그 중 가장 마지막(최근) 컬럼 값을 기준으로 한 줄로 정리한 뒤 새 제출 데이터로
  덮어씁니다.

## 알려진 한계

- 파일명 패턴이 예시(`F27-1234567_...`)와 크게 다르면 시즌/스타일/DESCRIPTION 자동 추출이
  틀릴 수 있습니다 → 화면에서 직접 수정 가능합니다.
- 원가 시트의 서식(열 배치)이 표준 템플릿과 크게 다르면 CM/CBS/REMARK/MARGIN % 위치를
  못 찾을 수 있습니다 → 이 경우 경고 메시지가 표시되거나 해당 칸이 비어 있습니다.
- 시트 탭 이름에 단계 키워드(P1~P3, GTM1/GTM2, SMS, PP)가 전혀 없으면 임시로 시트 이름
  일부를 STAGE 라벨로 사용합니다 → 표에서 직접 고쳐주세요.
- 단계별 변경점(diff) 비교는 참고용입니다. 시트 구조가 크게 다른 경우 자동으로 비교를
  생략하지만, 완벽하지 않을 수 있으니 최종 REMARK는 꼭 검토해주세요.
